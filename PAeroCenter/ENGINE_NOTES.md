# Устройство PAeroCenter 2.0.0

## Границы модулей

| Файл | Ответственность |
| --- | --- |
| `popup.html`, `popup.css`, `popup.js` | Только интерфейс: запуск, настройки, статус, экспорт и диагностика. Не выполняет длительный обход. |
| `background.js` | Валидация отправителя и вкладки, запуск исполнителя, сериализация изменений job, координация записи, экспорт, обработка закрытия вкладки. |
| `engine/collector.js` | Адаптер страницы ADVANTA: DOM, раскрытие, виртуальная прокрутка, последовательные GET/POST для часов, остановка. |
| `engine/recorder.js` | Пассивный CDP Network observer, ограниченный выбранными tabId/origin и типами Fetch/XHR. |
| `engine/core.js` | Чистые функции: ограниченный parser, DX, сопоставление виджетов, порядок строк, маскирование, CSV. |
| `engine/store.js` | IndexedDB: таблицы jobs и network, индекс network.jobId. |

Все runtime-файлы — обычный JavaScript без сборки и внешних зависимостей. Background загружает общие функции через importScripts; в изолированный мир страницы внедряются core.js и collector.js, после чего явно вызывается start(). Никакого динамического исполнения ответов сервера нет.

## Жизненный цикл

UI → START → background создаёт job → (необязательно) attach recorder → injection collector → моментальный ответ UI.

Collector работает независимо от popup. Состояние и ряды отправляются как COLLECTOR_EVENT. Background сериализует изменения одного job, чтобы поздний checkpoint не затёр финальный результат. Финальные состояния не принимают обычных поздних обновлений.

Статусы: running / recording / stopping / completed / partial / error / stopped / interrupted. Этапы: structure / hours / network / done.

Checkpoint строк — примерно раз в 4 секунды при активности, heartbeat — раз в 5 секунд. Сохранение зависит от доступности хранилища и runtime. При закрытии страницы последние ещё не сохранённые данные могут быть потеряны. Состояния не хранятся только в глобальных переменных service worker: jobs и записи находятся в IndexedDB. Фактическая сессия debugger остаётся в памяти; после перезапуска требуется новый явный запуск.

## Запуск и сообщения

Команды UI: PROBE, START, STOP, STATE, EXPORT, EXPORT_DIAGNOSTIC, CLEAR. Доступны только страницам данного расширения. Входящие сообщения сайта не используются как команды управления. Нет внешнего window.postMessage-моста.

COLLECTOR_EVENT принимается только от главного frame нужной вкладки, для известного job и соответствующего origin. Между background и content script используются runtime.sendMessage/tabs.sendMessage, а не переменные в MAIN world.

## Сбор структуры

Селекторы сосредоточены в объекте S в collector.js. Поиск точного сгенерированного класса вроде `_switchImage_nz6me_8` заменён на `img[src*="plusGray"]` внутри известного дерева. Синтетические клики ограничены раскрытием идентифицируемых строк.

Один только Map сохраняет порядок первого обнаружения, поэтому появившиеся позже дочерние строки оказались бы в конце CSV. Здесь каждое наблюдаемое окно DOM добавляет отношения порядка между соседними UID. Топологическая сортировка восстанавливает порядок обхода, сохраняя старые транзитивные связи. При противоречиях все строки сохраняются, но появляется предупреждение; это не замена серверного parentId.

Внутри строк нет правдоподобных заглушек `0%` или `0 часов`. Неизвестные значения — null. UID — ключ дедупликации. Исходные названия не дополняются отступами: вложенность хранится отдельно.

## Часы

На текущей карточке используются её DOM-ключи. Для другого UID сначала выполняется GET его URL и DOMParser извлекает его __VIEWSTATE_KEY / __CONTROLLER_KEY. Далее POST того же URL к `ctl34$cbKeyMeasureWidgets` с параметром callback из старого образца. Никакие перенаправления не следуются автоматически (`redirect:error`).

Разбор требует ожидаемого DX-маркера и структуры. Ограниченный parser понимает строки, объекты, массивы, конечные числа, true/false/null, комментарии и конечные запятые. Функции, выражения, NaN, произвольные идентификаторы и prototype-ключи отвергаются. Неподдерживаемое не исполняется и не «угадывается».

Нужны реальные проверки: действительный callback ID; необходимый состав полей; поведение с ключами на карточках; названия полей виджетов; порядок/идентификаторы виджетов и единицы чисел. Тестовые fixture эти неизвестные не подтверждают.

## Регистратор

Подписки Network.requestWillBeSent / responseReceived / loadingFinished / loadingFailed, затем Network.getResponseBody. Используются только Network.enable/getResponseBody; нет Fetch interception, replayXHR, setExtraHTTPHeaders, cookies API или прокси.

Сначала маскирование разрешённых полей, затем запись в IndexedDB. POST-data, отсутствующие в событии, отмечаются как недоступные; расширение не обещает извлечь любой upload. Перенаправления и незавершённые запросы обозначаются. Binary/HTML/unknown тела не хранятся. Большие структурированные ответы тоже опускаются явно. При лимите запись заканчивается независимо от DOM-сборщика.

`debugger` — обязательное разрешение манифеста, запись активируется только пользователем. Оно технически более широкое, чем реализованная функция; перечисление в манифесте нельзя считать разрешением организации на использование. Корпоративная политика/другой debugger могут препятствовать attach; ошибка показывается, обходов нет.

## Намеренно не добавлено

Редактирование карточек, массовые изменения, синхронизация с облаком, искусственный интеллект в runtime, удалённое управление браузером, распознавание любых вариантов ADVANTA, полная копия серверной базы, возобновление после перезапуска, WebSocket/worker/iframe capture и полные необезличенные HAR.
