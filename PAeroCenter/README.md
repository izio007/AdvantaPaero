# PAeroCenter — восстановление движка 2.0.0

Готовая к загрузке папка расширения Chrome Manifest V3. Сборка через npm, Python, Node.js или интернет **для использования не нужна**. Все исходники уже включены.

**Статус:** восстановительная сборка для проверки. Логика прошла автоматические проверки на синтетических данных; работа с реальной ADVANTA и фактическими Chrome Extension API в вашей среде ещё не подтверждена. Подробности в `TEST_REPORT.md`.

## Установка

1. Оставьте исходную папку `образцы` без изменений. Если старое расширение установлено, выключите его на время проверки.
2. Поместите эту папку `PAeroCenter` в `D:\workspace\AdvantaPaero`. Получится `D:\workspace\AdvantaPaero\PAeroCenter\manifest.json`.
3. В Chrome откройте `chrome://extensions`, включите **Режим разработчика**, нажмите **Загрузить распакованное расширение** и выберите именно папку с `manifest.json`.
4. Закрепите PAeroCenter на панели расширений. Откройте ADVANTA и войдите своей штатной учётной записью.
5. Откройте небольшую структуру проекта и нажмите значок PAeroCenter → **Проверить страницу**. Это проверяет распознавание, но не раскрывает дерево и не запрашивает часы.
6. Для первого пробного сбора нажмите **Собрать видимые строки**. После сверки данных можно использовать **Запустить сбор** для обхода дерева.

Если организация запрещает установку расширений или разрешение `debugger`, требуется разрешённый администратором вариант развёртывания. Обход политик не предусмотрен.

## Основной запуск

**Запустить сбор** выполняет цепочку:

`проверка вкладки → запись обмена (если включена) → раскрытие дерева и накопление строк → запрос часов (если включён) → локальный checkpoint → CSV`

Код в консоль вставлять не нужно. Можно закрыть окно расширения. Саму вкладку ADVANTA во время выполнения не закрывайте, не обновляйте, не сортируйте и не меняйте фильтры. Не запускайте второй автоматизатор одновременно.

Флажок **Записать обмен** включает отдельный пассивный регистратор XHR/Fetch. Если подключение отладчика отклонено, сборщик структуры пытается продолжить работу и показывает предупреждение. Разрешение debugger при этом всё равно объявлено в манифесте: Chrome не позволяет объявлять его необязательным.

Флажок **Запросить часы** добавляет последовательный запрос показателей для обнаруженных карточек. Для дочерней карточки сначала читаются **её собственные** ключи состояния; ключи родительского проекта не подставляются за все дочерние. Названия callback и схема виджетов взяты из ваших образцов и требуют первой сверки на реальном сайте.

**Остановить** прерывает сбор и текущий запрос; уже собранные строки сохраняются как частичный результат. Закрытие/перезагрузка вкладки оставляет последний сохранённый checkpoint, а не гарантированно все последние строки. Автоматического продолжения после перезапуска браузера нет.

## Результаты

CSV передаётся через Chrome Downloads в подпапку `PAeroCenter` стандартной папки загрузок. Настройки Chrome и корпоративные политики могут потребовать диалог сохранения. Кнопка **CSV для Excel** позволяет повторить экспорт.

CSV — это текстовый файл UTF-8 с BOM и разделителем `;`, **не XLSX**. Содержит прежние 16 колонок плюс UID, статус сопоставления часов, ошибку и статус запуска. Ссылки записываются обычным текстом, а не выполняемыми формулами. Серверные строки, начинающиеся с символов формул, экранируются.

**Отчёт + обмен JSON** — состояние запуска, строки, предупреждения и сетевые записи. **Сохранить диагностику** — только признаки распознавания страницы, счётчики и используемые селекторы, без значений ключей состояния. Диагностика всё же содержит URL и название страницы: проверяйте её перед передачей.

В выпадающем списке показаны последние 20 запусков; более старые записи автоматически не удаляются. **Очистить локальный журнал** с подтверждением удаляет ВСЕ локальные записи расширения, но не исходники и не ранее скачанные файлы.

## Что реализовано

- Единый исполнитель без ошибочного `import/export` внутри напрямую внедряемых сценариев.
- Сбор DOM-строк по UID, а не по названию; сохранены руководители, исполнители, даты, приоритеты, статусы и проценты.
- Накопление данных при виртуальном скролле и раскрытии; сохранение порядка «родитель → дети → следующий сосед» через ограничения порядка.
- Разбор безопасного подмножества литералов DevExpress без `eval` и `Function`. Неподдерживаемый ответ становится явной ошибкой, а не нулём.
- Отдельные состояния: выполнение, запись, остановка, завершение, частичный результат, ошибка, прерывание.
- Пассивный сетевой журнал, проверка страницы, ручная остановка, checkpoints и CSV/JSON.

Старые неработающие кнопки редактирования задач, графиков и анализа часов в эту сборку не перенесены. Изменение задач на сервере не реализовано. Сборщик раскрывает элементы интерфейса и отправляет предполагаемые запросы чтения показателей по схеме вашего образца; это не «вообще без HTTP-запросов».

## Границы и ограничения

Это сбор **доступной пользователю структуры**, а не выгрузка всей серверной базы. Вложенность, не переданная странице, другой iframe, другой интерфейс, серверная пагинация вне дерева и отличающиеся селекторы могут потребовать адаптера. Успешное достижение нижнего края прокрутки не доказывает полноту базы. При отсутствии явного aria-level уровень выводится из отступа 26 px, как в исходном образце; это оценка, а не подтверждённый серверный parent ID.

Показатели часов сначала сопоставляются по известным идентификаторам виджетов. Если идентификаторы не переданы, используется порядок из старого образца и ставится **positional-unverified**. Такие значения надо сверить с экраном; они не обозначаются как подтверждённые.

Сетевой регистратор: только XHR/Fetch выбранной вкладки с тем же origin (схема + хост + порт). Не охватывает весь компьютер, все вкладки, WebSocket, дочерние worker/iframe targets, загрузки документов и запросы других origin. Это не полный HAR и не система изменения или повторной отправки перехваченных запросов.

Записываются безопасно разобранные JSON, data-literals, DevExpress и form-urlencoded; произвольный HTML, неразобранный текст и бинарные тела опускаются с указанием причины. Заголовки Cookie, Set-Cookie и Authorization не включены в разрешённый список. Распознанные секретные поля маскируются перед записью. Маскирование **не гарантирует обезличивания**: названия, исполнители, бизнес-данные и нестандартные секреты могут оставаться.

Лимиты одного запуска: 5 000 узлов; 1 000 карточек с часами; 30 минут; 20 секунд на запрос; 3 подряд ошибки часов останавливают этот этап; пауза 600 мс между карточками. Журнал обмена: 1 000 записей / 4 МиБ; ограничение чтения тела 512 КиБ и сохранённой структуры одного ответа 128 КиБ. Ограничения и пропуски показываются, результат не объявляется полной копией базы.

## Данные и безопасность

Расширение не подключает LLM, аналитику, облачный сервер, CDN или внешний сборщик. Его собственные запросы ограничены origin выбранной вкладки. Сам сайт ADVANTA может выполнять свой обычный сетевой обмен — это поведение сайта, не расширения.

Состояния и журналы находятся в IndexedDB профиля Chrome, а выгрузки — в локальных загрузках. Это **не зашифрованное хранилище**: доступ к профилю/компьютеру и корпоративные средства управления могут дать доступ к файлам. Учётные данные используются штатной сессией браузера; расширение не требует ввода пароля. Корпоративные ограничения доступа сохраняются.

Рабочие CSV, JSON и сетевые дампы не добавляйте в публичный GitHub. Файл `.gitignore` здесь действует на новые неотслеживаемые файлы в этой папке, а не удаляет уже опубликованные материалы из истории чужого репозитория.

## Для разработчика

`ENGINE_NOTES.md` описывает устройство движка и протокол сообщений. `TEST_REPORT.md` — выполненные проверки и непроверенные границы.

Быстрые тесты при установленном Node.js 20+:

```bash
node --test tests/*.test.cjs
```

`tests/browser_smoke.py` проверяет настоящий DOM и таймеры в Chromium, но использует имитацию location/fetch/chrome.runtime. Требуются Python и Playwright только на машине разработчика; путь к Chromium задаётся переменной `CHROMIUM`.

`tests/extension_integration.py` — отдельный тест фактического расширения на локальном HTTP-стенде. Он подготовлен, но в текущей среде выполнение заблокировано административной политикой. В тестовой копии он добавляет разрешение **только на loopback-хост** для управления стендом. Исходный манифест остаётся без постоянных host_permissions. Для проверки реального activeTab нужен обычный пользовательский запуск через значок расширения.
